# AGENTS.md — память проекта для ИИ-агентов

> Этот файл автоматически загружается Kilo Code в КАЖДОЙ сессии. Держи его компактным (~100 строк):
> детали — в `docs/DECISIONS.md`, планы — в `docs/ROADMAP.md`. После каждого существенного изменения
> кода обнови «Карту кода» и добавь запись в журнал решений (правило см. ниже).

## Дисциплина ведения (для агента, обязательно)

1. **Любое принятое решение** (архитектурный ход, выбор подхода, найденный и понятый баг, отсечённая альтернатива) — одна запись в `docs/DECISIONS.md` в том же сеансе, когда решение принято. Формат: дата, статус, проблема, решение, затронутые функции, верификация.
2. **При каждой версии (деплой/публикация)** — обновить `APP_VERSION` и ДОБАВИТЬ СТРОКУ СВЕРХУ блока `APP_DESCRIPTION` в main.py (вкладка «Об агенте»); формат: `<версия> - кратко об изменениях.` Хранить в блоке НЕ БОЛЕЕ 3 последних версий (самую старую из трёх удалять, вместо неё в блоке дежурная строка «Полная история изменений: docs/DECISIONS.md»); подробности версий — всегда в `docs/DECISIONS.md`. Правило действует всегда, не только для крупных фич.
3. **Номера строк в main.py дрейфуют** — в логах ссылайся в первую очередь на имена функций; номера строк давай как «на дату записи».
3. Не дублируй README.md (он для пользователей). AGENTS.md — это карта для агентов.

## Проект

**ИИ-Агент СМК** — автономный RAG-агент для Системы Менеджмента Качества предприятия.
Monolith: почти вся логика в `main.py` (~8.8k строк). Подробности возможностей — `README.md`.

## Прод, сборка и деплой

- ПРОД-агента ДВА (каждый на своей базе; операции над базами — для каждого отдельно): `Z:\Производство\Проекты производства\1603 СМК Полюс-СТ\AI Agent SMQ Gr` и `Z:\...\1603 СМК Полюс-СТ\Ai Agent SMQ GOZ`. У каждого свой base (file_states.json, smk_vector_db) и свой профиль SMK_Agent_* в LOCALAPPDATA админ-машины (профилей ≥3 с dev — guard-скрипты проверяют ВСЕ).
- Сборка — ТОЛЬКО `build_agent.bat` (не pyinstaller напрямую): релиз `dist\SMK_Agent_Build_<дата>` + ZIP, в конце pause. Версия внутри exe проверяется через PyInstaller CArchiveReader (`build\SMK_Agent\SMK_Agent.pkg` → entry `main`).
- Деплой — `Деплой на сервер.bat` (robocopy /E, базы не трогает), в каждую прод-папку отдельно; пользователь обычно деплоит сам. Перед операциями над базами — страховка: копии `smk_vector_db` обеих баз, удалить после успеха.

## Стек (строго)

GUI: `customtkinter` (обычный tkinter запрещён) · Вектора: `chromadb` (коллекция `smk_docs`) · PDF: только `PyMuPDF` (`import fitz`; PyPDF2/pdfplumber запрещены) · LLM: `openai` через OpenRouter (Vision-модели, Graph RAG на дешёвых моделях) · Схемы: `xml.etree` (yEd `.graphml`) · SQLite: `graph_rag.db` (WAL) · Excel: `openpyxl` + `pandas` · Аудио: Whisper через OpenRouter.

## Железные правила (полная версия: .kilocode/rules/Rules for Kilo Code.md)

- Тяжёлые операции (парсинг, API, эмбеддинг) — только в `threading.Thread`; GUI из потока — только `self.after(0, lambda: ...)`.
- Хирургические правки main.py: не переписывать файл целиком; правки в стиле «Что найти → На что заменить».
- Кэш тяжёлых экстракций: `./SMK_Docs/.cache/` (и `.cache/xwiki_sync/`), чтение кэша если mtime кэша >= mtime оригинала.
- Никаких тихих падений: try/except + понятные сообщения в GUI-логи (какой файл/шаг упал).
- Комментарии/логи/UI — на русском; имена функций/переменных — snake_case на английском.
- Никаких комментариев в коде, если об этом не попросили; не коммитить без явной просьбы.
